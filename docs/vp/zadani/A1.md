# A1+A2 Registrace e-mailem (heslo volitelné), přihlášení e-mailem i jménem, přihlašovací odkaz

- **Větev roadmapy:** V1 Registrace (viz [ROADMAP.md](../ROADMAP.md))
- **Issue:** #44
- **Řešitel:** Claude
- **Stav zadání:** schváleno (Petr, 2. 11. 2026 – pokyn k implementaci)

## Cíl

Externí zájemce se zaregistruje e-mailem, heslo je volitelné; přihlašovací jméno (login) se mu vygeneruje z e-mailu a nemusí ho znát.
Přihlašuje se e-mailem a heslem nebo přihlašovacím odkazem; kdo má jméno, přihlásí se dál i jménem. Zapomenuté heslo řeší přihlašovací odkaz.
Změna akce: „Registrace ve 30 s“ a „Přihlášení bez hesla“ (R 2, R 10).

## Rozhodnutí (Petr, 1. 11. 2026)

- **E-mail je přihlašovací údaj, `login.login_name` je vnitřní klíč.** Na `login_name` visí cizí klíče v events a synchronizace,
  struktura se nemění. Administrace a ruční dokončení registrace zástupce firmy pracují dál se jménem účtu.
- **Dvě kategorie účtů:**
  - *externí* – vznikají registračním formulářem: e-mail, heslo volitelné (i u zástupce firmy), login generovaný z e-mailu, role `visitor` po potvrzení;
    e-mail je mezi účty z registrace jedinečný (druhý účet na stejný e-mail registrace nevytvoří);
  - *interní* (editor, supervisor, events_administrator, testovací visitor/representative) – zakládá je administrátor formulářem
    přes API (balík **A6**, #72), e-mail povinný, ale nemusí být jedinečný, jméno lze zadat ručně.
- **Přihlášení:** pole „E-mail nebo přihlašovací jméno“ + heslo. E-mailem se přihlásí jen ten, komu e-mail patří jedinému účtu;
  při více účtech s jedním e-mailem je přihlášení jen jménem. Stávající účty (i 13 bez e-mailu) se přihlásí jako dosud.
- **Zástupce firmy:** jeden účet na zástupce, jeden účet může zastupovat víc firem (tabulka `representative`, už dnes).
  Zaškrtnutí „Žádám o registraci jako zástupce firmy“ zůstává; roli `representative` přidělí ručně pověřená osoba po ověření.

## Současný stav (zjištěno 1. 11. 2026, dump baseline auth)

- Registrace (`RegistrationControler::register`): povinné jméno, heslo, e-mail. Heslo do potvrzení čitelně v
  `registration.password_hash` (záměr, Z6), potvrzení `GET auth/v1/confirm/:uid` vytvoří `credentials` s rolí `visitor`.
- Přihlášení (`LoginLogoutControler::login`): jméno + heslo. Zapomenuté heslo pošle nové heslo čitelně e-mailem.
- E-mail je jen v `registration.email`, bez indexu. 158 registrací, 134 různých e-mailů; **8 e-mailů má víc potvrzených účtů**
  (podle Petra interní a testovací účty) – tyto e-maily se nebudou dát použít k přihlášení, jen jméno.
- 13 loginů nemá registraci ani e-mail (správci, redakce) – přihlášení jménem beze změny.
- Pravidlo jména `\w{5,}`; `login.login_name` varchar(50), utf8mb3, porovnání bez ohledu na velikost písmen.
- Nález: `DbHashAuthenticator` má záložní ověření „heslo === uložená hodnota“ (staré nehashované hesla; 3 účty). Mimo rozsah,
  jen pojistka: prázdný uložený hash nikdy neprojde (viz Rozhraní).

## Rozsah

Patří sem:
- **A1 registrace:** formulář e-mail + heslo volitelně (+ zaškrtnutí „zástupce firmy“ a název firmy jako dnes). Login se generuje z e-mailu.
  Bez hesla se uživatel přihlašuje odkazem; heslo si může kdykoli nastavit (po přihlášení odkazem nebo v profilu).
  Registrace s e-mailem, který už má některý účet: nový účet nevznikne; potvrzený účet → pošle se přihlašovací odkaz,
  nepotvrzená registrace → znovu potvrzovací e-mail. Hláška na webu je ve všech případech stejná (neprozradí, zda e-mail u nás je).
- **Přihlášení e-mailem nebo jménem** + heslem (jedno pole).
- **A2 přihlašovací odkaz** (místo „zapomenuté heslo“): zadá e-mail → jednorázový odkaz s platností 30 minut (konfigurace) na každý účet
  s tímto e-mailem (u více účtů s uvedeným jménem účtu). Po přihlášení odkazem si uživatel může nastavit nové heslo.
- Potvrzení registrace scanner-bezpečně (GET ukáže tlačítko, POST potvrdí) a rovnou přihlásí.

Nepatří sem:
- zakládání účtů administrátorem, API pro to a zrušení `register1` (A6, #72);
- úklid nepotvrzených registrací, texty o ochraně dat, mobil (A3–A5, #45);
- hashování hesla hned při registraci a heslo v e-mailu Grafii (Z6, #38);
- změna e-mailu účtu (později, potvrzení nového e-mailu odkazem);
- unikátní index na e-mail v DB (jedinečnost hlídá aplikace jen pro účty z registrace).

## Databáze

Migrace `migrations/auth/2026110xxxxxxx_login_token.sql` (ověřeno na kopii DB auth, MariaDB 10.11; MySQL 8 ověří Petr):

```sql
CREATE TABLE login_token (
  token_hash CHAR(64) CHARACTER SET ascii NOT NULL,
  login_name_fk VARCHAR(50) CHARACTER SET utf8mb3 COLLATE utf8mb3_general_ci NOT NULL,
  purpose VARCHAR(20) CHARACTER SET ascii NOT NULL DEFAULT 'login',
  created DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  expires DATETIME NOT NULL,
  used DATETIME NULL DEFAULT NULL,
  PRIMARY KEY (token_hash),
  KEY login_token_login_idx (login_name_fk, created),
  CONSTRAINT login_token_login_fk FOREIGN KEY (login_name_fk) REFERENCES login (login_name)
    ON UPDATE CASCADE ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

ALTER TABLE registration ADD INDEX registration_email_idx (email);
```

- Nová tabulka v `utf8mb4`; sloupec s cizím klíčem má znakovou sadu rodiče (`login` je utf8mb3), jinak cizí klíč nevznikne.
- V DB je jen **SHA-256 hash tokenu**, token je jen v e-mailu.
- Index na e-mail je neunikátní (interní účty mohou e-mail sdílet).
- Existující data se nemění. Návrat zpět: `DROP TABLE login_token; ALTER TABLE registration DROP INDEX registration_email_idx;`

## Rozhraní

**Generování loginu z e-mailu** – `Auth\Model\LoginNameGenerator` (použije i A6, když administrátor jméno nezadá):
1. část před `@`, malá písmena, diakritika na ASCII, znaky mimo `[a-z0-9_]` → `_`, více `_` → jedno, `_` na okrajích pryč,
   zkrátit na 46 znaků;
2. prázdný výsledek → `ucastnik`; kratší než 5 znaků → doplnit číslem na 5 znaků (`jan` → `jan01`, `ab` → `ab001`);
3. při shodě s existujícím loginem (bez ohledu na velikost písmen) přípona `2`, `3`, … (`petr_novak2`), max. 50 znaků.

**Přihlášení** (`LoginLogoutControler::login`): obsahuje-li zadaný údaj `@`, jde o e-mail (jméno `@` obsahovat nemůže):
- najdou se potvrzené účty s tímto e-mailem (`registration.email`, porovnání bez ohledu na velikost písmen a mezery na okrajích);
- právě jeden → ověří se heslo; žádný → „Neplatné přihlášení“; víc → „K tomuto e-mailu patří víc účtů, přihlaste se jménem.“;
- jinak jméno jako dnes. `superlogin` beze změny.

**Routy** (`AuthRouteCatalog`):

| Metoda | Routa | Kontrolér | Přepínač | Co dělá |
|---|---|---|---|---|
| POST | `/auth/v1/register` (stávající) | `RegistrationControler::register` | `vp.registrace-emailem` | e-mail + heslo volitelně, login generovaný, kontrola e-mailu |
| POST | `/auth/v1/login` (stávající) | `LoginLogoutControler::login` | `vp.registrace-emailem` | přihlášení e-mailem nebo jménem |
| POST | `/auth/v1/loginlink` | `LoginLinkControler::send` | `vp.prihlaseni-odkazem` | pošle odkaz(y); odpověď vždy stejná |
| GET | `/auth/v1/loginlink/:token` | `LoginLinkControler::confirmPage` | `vp.prihlaseni-odkazem` | stránka s tlačítkem „Přihlásit se“ (GET token nespotřebuje) |
| POST | `/auth/v1/loginlink/:token` | `LoginLinkControler::login` | `vp.prihlaseni-odkazem` | ověří hash, platnost, nepoužitý → `used`, přihlásí |
| GET/POST | `/auth/v1/confirm/:uid` | `ConfirmControler` | `vp.registrace-emailem` | GET tlačítko „Dokončit registraci“, POST potvrdí a přihlásí |

- Model: `LoginTokenDao/Repo`, entita `LoginToken`; v `RegistrationDao` vyhledání podle e-mailu (všechny / jen potvrzené).
- Token: 32 bajtů `random_bytes`, v odkazu base64url, v DB `hash('sha256', …)`. Nejvýš 3 odkazy na účet za 15 minut.
- **Konfigurace** (`ConfigurationAuth`): `loginLinkTtlMinutes` (30), `loginLinkLimitCount` (3), `loginLinkLimitMinutes` (15).
- **Pravidlo hesla** zůstává v konfiguraci (`passwordPattern`, `passwordInfo`): nově aktivní `.{8,}` („aspoň 8 znaků“),
  stávající pattern (velké + malé písmeno + číslice, min. 5) v konfiguraci zakomentovaný. Platí pro registraci, změnu hesla i A6.
- `DbHashAuthenticator`: prázdný uložený hash → `false` (pojistka).
- Nastavení hesla bez starého hesla: v sezení přihlášeném odkazem (po dobu platnosti odkazu) a u účtu, který heslo nemá.
- Adresa odkazu jako dnes u potvrzení registrace (host + base path); po Z12 z konfigurace.
- **Šablony** (`local/site/najdisi/templates/layout/status/`, výběr přes `FeatureFlags`): registrace (e-mail, heslo „nepovinné“, zástupce firmy),
  přihlášení („E-mail nebo přihlašovací jméno“, heslo, odkaz „Zapomněli jste heslo? Pošleme přihlašovací odkaz“).
- **E-maily** (`MailSettings`): nový `loginlink.php`; `registration.php` bez jména, s e-mailem;
  e-mail o dokončení registrace uvede vygenerované jméno účtu (pro komunikaci s organizátorem);
  e-mail Grafii o zástupci firmy bez hesla uvede „bez hesla – přihlašuje se odkazem“.
- Role: beze změny – po potvrzení `visitor`; `representative` ručně (administrace, beze změny).

## Přepínač

- `vp.registrace-emailem` – vypnuto: registrace, potvrzení i přihlášení jako dnes (jméno + heslo).
- `vp.prihlaseni-odkazem` – vypnuto: routy `loginlink` vrací 404, ve formuláři je původní „zapomenuté heslo“.
- Oba v `app/Site/NajdiSi/ConfigurationFeatures.php`, výchozí `false`; zapínat najednou.

## Akceptační kritéria

1. Registrace `jan.novak@example.test` + heslo vytvoří login `jan_novak` (při shodě `jan_novak2`), přijde potvrzovací e-mail;
   po potvrzení tlačítkem je účet aktivní s rolí `visitor` a uživatel přihlášený.
2. Přihlášení `jan.novak@example.test` + heslo i `jan_novak` + heslo funguje. Účet registrovaný bez hesla se přihlásí odkazem,
   heslem (ani prázdným) ne, dokud si heslo nenastaví – platí i pro zástupce firmy.
3. Registrace se stejným e-mailem nevytvoří druhý účet; web odpoví stejně jako u nového e-mailu.
4. U e-mailu se dvěma účty přihlášení e-mailem odmítne s výzvou zadat jméno; jménem projde.
5. Účty bez e-mailu a stávající účty se přihlásí jménem jako dnes.
6. Přihlašovací odkaz funguje jednou do 30 minut; u e-mailu se dvěma účty přijde jeden e-mail se dvěma odkazy a jmény účtů;
   pro neznámý e-mail web odpoví stejně a nic se nepošle.
7. Zaškrtnutý „zástupce firmy“ funguje jako dnes (e-mail Grafii, role `representative` ručně).
8. V DB není čitelný token; s vypnutými přepínači se vše chová jako dnes; ostatní sites beze změny.
