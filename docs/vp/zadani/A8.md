# A8 Osobní jméno uživatele

- **Větev roadmapy:** V1 Registrace (viz [ROADMAP.md](../ROADMAP.md))
- **Issue:** #85
- **Řešitel:** Claude
- **Stav zadání:** schváleno (Petr, 6. 11. 2026 – pokyn k implementaci)

## Cíl

Uživatel si může zadat své osobní jméno (např. „Jan Novák“) – nepovinně už při registraci, nebo kdykoli později přidat,
změnit či smazat. Web ho zobrazuje v okně odhlášení a v uživatelských akcích místo přihlašovacího jména.

## Rozhodnutí (Petr, 6. 11. 2026)

- Přihlašovací jméno (`login.login_name`) zůstává generovaný vnitřní klíč; osobní jméno není klíč ani přihlašovací údaj.
- Uživatel registrovaný formulářem se dál přihlašuje e-mailem + odkazem nebo heslem.
- Uživatel přihlašovaný jménem + heslem si osobní jméno může zadat také.
- Nahrazuje požadavek „vlastní přihlašovací jméno při registraci“ z #84.

## Rozsah

Patří sem:
- nepovinné pole „Vaše jméno“ v registraci e-mailem (A1);
- formulář „Změnit jméno“ v okně odhlášení (přidat, změnit, smazat = prázdné pole);
- zobrazení osobního jména v okně odhlášení, v akcích editora a zástupce firmy; bez osobního jména se zobrazuje
  přihlašovací jméno jako dnes;
- osobní jméno ve formuláři zakládání účtu administrátorem (A6, pokud půjde po A8).

Nepatří sem: osobní jméno v e-mailech, ve výpisech pro firmy a v profilu návštěvníka (později s H2).

## Závislosti

A1 (registrace e-mailem) v `master-vp`.

## Databáze

Migrace `migrations/auth/20261106000001_login_profile.sql` – nová tabulka, existující tabulky beze změny:

```sql
CREATE TABLE login_profile (
  login_name_fk VARCHAR(50) CHARACTER SET utf8mb3 COLLATE utf8mb3_general_ci NOT NULL,
  display_name VARCHAR(100) NULL DEFAULT NULL,
  updated DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (login_name_fk),
  CONSTRAINT login_profile_login_fk FOREIGN KEY (login_name_fk) REFERENCES login (login_name)
    ON UPDATE CASCADE ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

Proč samostatná tabulka a ne sloupec v `login`: `LoginDao` čte vyjmenované sloupce a používají ho všechny sites;
nový sloupec v `login` by bez migrace rozbil přihlášení na ostatních sites. Tabulku `login_profile` čte jen nový kód
a jen při zapnutém přepínači. Smazání účtu (i úklid A3) smaže osobní jméno kaskádou. Návrat: `DROP TABLE login_profile`.

## Rozhraní

- Routa (`AuthRouteCatalog`, `$feature = 'vp.osobni-jmeno'`): `POST /auth/v1/displayname` → `DisplayNameControler::change`
  (jen přihlášený uživatel, jinak 401), pole `displayName`; po uložení flash a přesměrování zpět.
- Registrace e-mailem: pole `displayName` (nepovinné), uloží se při registraci.
- Pravidla: oříznout mezery, víc mezer za sebou sloučit, odstranit řídicí znaky, nejvýš 100 znaků; prázdné = smazat.
  Na výstupu vždy escapovat.
- Zobrazení: osobní jméno se načte při přihlášení (všechny cesty – jméno + heslo, odkaz, dokončení registrace) do stavu
  session (`Security::setInfo`), `StatusViewModel::getUserDisplayName()`; šablony použijí osobní jméno, jinak přihlašovací.
- Služba `Auth\Service\DisplayNameService` (normalizace, čtení, uložení) nad `LoginProfileDao`.

## Přepínač

`vp.osobni-jmeno` – vypnuto: pole v registraci a formulář změny jména se nezobrazí, routa vrací 404, zobrazuje se
přihlašovací jméno jako dnes, tabulka `login_profile` se nečte.

## Akceptační kritéria

1. Registrace e-mailem s vyplněným jménem „Jan Novák“ → po dokončení registrace okno odhlášení ukazuje „Jan Novák“.
2. Registrace bez jména → okno odhlášení ukazuje přihlašovací jméno jako dnes.
3. Přihlášený uživatel (i přihlašovaný jménem + heslem) jméno přidá, změní a smaže; změna se projeví hned.
4. Přihlášení e-mailem + heslem, odkazem i jménem + heslem ukazuje uložené osobní jméno.
5. Jméno s HTML (`<b>x</b>`) se zobrazí jako text.
6. Nepřihlášený `POST /auth/v1/displayname` → 401, nic se neuloží.
7. Vypnutý přepínač = vše jako dnes; ostatní sites beze změny.
