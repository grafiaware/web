# D1 Losování pro registrované (+ D1b online kategorie)

- **Větev roadmapy:** V2 Losování (viz [ROADMAP.md](../ROADMAP.md))
- **Issue:** #46
- **Řešitel:** Claude
- **Stav zadání:** návrh (1. 11. 2026) – čeká na schválení Petrem a pravidla soutěže od organizátora; obsahuje změnu DB events

## Cíl

Do losování se zapojí jen registrovaný návštěvník jedním kliknutím ve svém profilu; za doplněný profil dostane los navíc.
Organizátor v administraci vylosuje výherce, výherce to uvidí v profilu a dostane e-mail.
Změna akce: „Losování jen pro registrované, losy za profil, losování v aplikaci“ (R 3.1, R 4, S 5)
a volitelně „Online losování pro nepřítomné“ (R 7, D1b).

## Současný stav

- Losování dnes běží mimo web: na úvodní stránce a v profilu návštěvníka je odkaz na anketu
  (`local/site/najdisi/static/vp/uvod/content/program.php`, `vp-profil-navstevnika/template.php`) a „slosování o ceny“.
- DB events nemá nic pro losování. Účet návštěvníka je v events v tabulce `login` (vzniká synchronizací Z1 při prvním
  přístupu přihlášeného uživatele), profil v `visitor_profile` (jméno, příjmení, telefon, CV, dopis).
- E-mail účtu je jen v DB auth (`registration.email`).

## Rozsah

Patří sem:
- **Losování** (může jich být víc, např. „Veletrh 2027 – na místě“ a „Veletrh 2027 – online“): název, popis, odkaz na pravidla,
  od kdy do kdy se lze zapojit, termín losování, stav (příprava → otevřeno → uzavřeno → vylosováno), příznak online (D1b).
- **Ceny:** název, počet kusů, volitelně firma, která cenu věnuje (`company`), pořadí losování.
- **Zapojení:** v profilu návštěvníka tlačítko „Zapojit se do losování“ se souhlasem s pravidly → los za registraci.
  Při uzavření losování se přidá los navíc za doplněný profil (pravidlo níže). Návštěvník vidí, v kterých losováních je a kolik má losů.
- **Losování v administraci** (role `events_administrator`): náhled počtu účastníků a losů, tlačítko „Vylosovat“
  (jedna cena nebo všechny), losy váží šanci, jeden účastník vyhraje v jednom losování nejvýš jednu cenu
  (zda i napříč losováními, např. na místě a online, určuje konfigurace `lottery.oneWinAcrossLotteries`, výchozí ne);
  výherce lze označit „nepřítomen / nepřevzal“ a vylosovat náhradníka (u losování na místě); protokol (čas, počty, kdo losoval).
- **Dva způsoby losování na místě** (oba nad stejnou službou):
  - *projektor* – v administraci tlačítko „Losovat“, výsledek na samostatné celoobrazovkové stránce pro projektor
    (cena, křestní jméno výherce, žádný e-mail ani příjmení); stránka se obnovuje sama po každém tahu;
  - *telefon* – stránka administrace upravená pro mobil: velké tlačítko „Losovat“, výherce (jméno a příjmení pro vyvolání hlasem),
    tlačítka „Převzal“ / „Nepřítomen → losovat znovu“.
- **Výsledek:** výherce vidí v profilu „Vyhráli jste …“; e-mail výherci (šablona přes `MailSettings`).
  Na webu veřejně jen ceny a počet výherců, nikdy jména (rozhodnuto 2. 11.).
- Všechny procesy losování (na místě i online) se později zrevidují s organizátorem – úkol #74; nastavení, které se může
  změnit, je v konfiguraci.

Nepatří sem:
- losy za navštívené stánky (D2, V13 – po QR B1/B3), za přednášky, „přiveď kamaráda“ (F), studentské mise;
- ověření přítomnosti na místě přes QR (V4) – v D1 rozhoduje organizátor při losování („nepřítomen“ → náhradník);
- živé obrazovky a notifikace (PWA);
- ukazatel úplnosti profilu (H2b) – D1 použije jednoduché pravidlo, po H2b se nahradí.

## Závislosti

V `master-vp`: Z1 (#41), Z8 (#40), Z3 (#42) – sloučeno. Na hostingu musí před migrací D1 proběhnout Z4 (cizí klíče na `login`).
Souvisí s A1 (#44) – čím snazší registrace, tím víc účastníků; technicky nezávislé.

## Databáze

Migrace `migrations/events/2026110xxxxxxx_lottery.sql` – 4 nové tabulky v `utf8mb4`
(ověřeno na kopii DB events, MariaDB 10.11, včetně přejmenování loginu přes `ON UPDATE CASCADE`):

| Tabulka | Sloupce (zkráceně) |
|---|---|
| `lottery` | `id`, `name`, `description`, `online`, `status`, `join_from`, `join_until`, `draw_at`, `rules_url`, `created` |
| `lottery_prize` | `id`, `lottery_id_fk` → `lottery`, `name`, `quantity`, `company_id_fk` → `company` (SET NULL), `priority` |
| `lottery_ticket` | `id`, `lottery_id_fk`, `login_login_name_fk` → `login`, `reason` (`registrace`, `profil`, později `stanek`…), `created`; unikátní (losování, login, důvod) |
| `lottery_winner` | `id`, `lottery_id_fk`, `prize_id_fk`, `login_login_name_fk`, `drawn`, `status` (`drawn`, `absent`, `claimed`), `notified` |

- Sloupce s cizím klíčem na `login` mají znakovou sadu rodiče (utf8mb3), jinak cizí klíč nevznikne.
- Smazání loginu smaže jeho losy a výhry (`ON DELETE CASCADE`).
- Existující data se nemění. Návrat zpět: `DROP TABLE lottery_winner, lottery_ticket, lottery_prize, lottery;`
- Celé SQL je v příloze na konci zadání.

## Rozhraní

- Model (vzor modulu Events): `LotteryDao/Repo/Entity`, `LotteryPrize…`, `LotteryTicket…`, `LotteryWinner…`, hydrátory.
- Služba `Events\Service\LotteryDraw`: výběr výherce s vahou podle počtu losů (`random_int`, kryptograficky bezpečný),
  bez výherců z předchozích tahů téhož losování; čistá logika s rozhraním pro zdroj náhody (kvůli testům).
- **Losy navíc podle konfigurace** (`ConfigurationEvents` → `lottery.bonusRules`): seznam pravidel, každé = název důvodu
  (`reason` v `lottery_ticket`), počet losů a třída kontroly (rozhraní `Events\Service\Lottery\BonusRuleInterface`
  s metodou `isSatisfied(string $loginName): bool`). Nová pravidla (sken QR u stánku, účast na přednášce, „přiveď kamaráda“)
  se přidají jako další třída a řádek konfigurace, bez změny DB (důvod je text).
- **Pravidlo „doplněný profil“ teď** (`CompleteProfileRule`, 1 los): vyplněné `name` a `surname` (každé aspoň 2 písmena)
  a CV, které projde kontrolou:
  - nahraný dokument `cv_document` povoleného typu (PDF, DOC, DOCX, ODT) a velikosti aspoň `lottery.cv.minBytes` (návrh 10 kB), **nebo**
  - texty `cv_education_text` a `cv_skills_text` dohromady aspoň `lottery.cv.minChars` znaků (návrh 200), aspoň
    `lottery.cv.minWords` různých slov (návrh 30) a bez dlouhých opakování stejného znaku/slova.
  Parametry v konfiguraci. Obsah CV automaticky posoudit nejde – organizátor může v administraci los navíc ručně
  odebrat („CV nevyhovuje“) a návštěvníkovi zůstane los za registraci.
- Routy (`EventsRouteCatalog`, `$feature = 'vp.losovani'`):

| Metoda | Routa | Kdo | Co |
|---|---|---|---|
| POST | `/events/v1/lottery/:id/join` | přihlášený návštěvník | zapojení, souhlas s pravidly, los za registraci |
| POST | `/events/v1/lottery` , `/events/v1/lottery/:id` | `events_administrator` | založení a úprava losování |
| POST | `/events/v1/lottery/:id/prize`, `/events/v1/lottery/prize/:prizeId` (+ `/remove`) | `events_administrator` | ceny |
| POST | `/events/v1/lottery/:id/close` | `events_administrator` | uzavření, přidání losů podle pravidel |
| POST | `/events/v1/lottery/ticket/:ticketId/remove` | `events_administrator` | odebrání losu navíc (např. CV nevyhovuje) |
| POST | `/events/v1/lottery/:id/draw` | `events_administrator` | vylosování (cena nebo všechny) |
| POST | `/events/v1/lottery/winner/:winnerId/absent` | `events_administrator` | nepřítomen → náhradník |
| POST | `/events/v1/lottery/:id/notify` | `events_administrator` | e-maily výhercům |

- Šablony: blok „Losování“ v profilu návštěvníka (`local/site/najdisi/static/vp/vp-profil-navstevnika/…`),
  administrace losování v administraci events (`local/site/najdisi/static/…` podle stávajících admin stránek, použitelná na telefonu),
  projekční stránka `GET /events/v1/lottery/:id/screen` (jen `events_administrator`; bez osobních údajů kromě křestního jména),
  veřejný blok s cenami a počtem výherců,
  úprava textů na úvodní stránce (místo odkazu na anketu „Zapojte se v profilu“) – vše podle přepínače.
- E-mail výherci: `Events/.../Messages/lottery-winner.php` (cena, kde a dokdy převzít), adresa z DB auth
  (`LoginAggregateFullRepo` jako ve stávajících šablonách events; po Z12 přes API auth).
- Role: zapojit se může jen role `visitor`; zástupci firem (`representative`) ne (rozhodnuto 2. 11.).

## Přepínač

`vp.losovani` – vypnuto: routy vrací 404, v profilu ani administraci není blok losování, úvodní stránka zůstává s odkazem na anketu.

## Akceptační kritéria

1. Nepřihlášený návštěvník vidí výzvu „Zaregistrujte se a zapojte se do losování“, zapojit se nemůže.
2. Přihlášený návštěvník se zapojí jedním kliknutím se souhlasem s pravidly; mimo období `join_from`–`join_until` to nejde;
   podruhé se nezapojí (jeden los za registraci).
3. Po uzavření má návštěvník s doplněným profilem 2 losy, ostatní 1; počet losů vidí v profilu. CV z nesmyslného krátkého
   textu (např. „asdf asdf“) los navíc nedá; ručně odebraný los navíc se do losování nepočítá.
3a. Zástupce firmy se zapojit nemůže (tlačítko nevidí, API vrátí 403).
4. Vylosování: každá cena má tolik výherců, kolik má kusů (pokud je dost účastníků); nikdo nevyhraje dvakrát v jednom losování;
   statisticky odpovídá šance počtu losů (test na 10 000 tazích, tolerance).
5. „Nepřítomen“ u výherce vylosuje náhradníka na stejnou cenu; původní výherce se už nevylosuje.
6. Výherce vidí výhru v profilu, po odeslání dostane e-mail; e-mail se nepošle dvakrát (`notified`).
7. Online losování (D1b) funguje stejně, jen bez označení „nepřítomen“ a s textem o zaslání ceny.
8. Vypnutý přepínač = web jako dnes; ostatní sites beze změny.

## Testy

- Unit: pravidla losů navíc (`CompleteProfileRule` – hranice délky, počtu slov, opakování, typ a velikost dokumentu),
  `LotteryDraw` (váhy, bez opakování výherce, náhradník, málo účastníků, deterministický zdroj náhody),
  pravidlo doplněného profilu, šablona e-mailu výherci (`HtmlMessage`).
- Integrační: Dao všech čtyř tabulek, unikátnost losu, kaskády při přejmenování a smazání loginu.
- Ruční: založit losování a 2 ceny → 3 testovací návštěvníci se zapojí (jeden s profilem) → uzavřít → vylosovat →
  nepřítomen → náhradník → e-maily ve fake SMTP.

## Příloha: SQL migrace (návrh)

```sql
CREATE TABLE lottery (
  id INT UNSIGNED NOT NULL AUTO_INCREMENT,
  name VARCHAR(200) NOT NULL,
  description TEXT NULL,
  online TINYINT(1) NOT NULL DEFAULT 0,
  status VARCHAR(20) CHARACTER SET ascii NOT NULL DEFAULT 'draft',
  join_from DATETIME NULL DEFAULT NULL,
  join_until DATETIME NULL DEFAULT NULL,
  draw_at DATETIME NULL DEFAULT NULL,
  rules_url VARCHAR(500) NULL DEFAULT NULL,
  created DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE lottery_prize (
  id INT UNSIGNED NOT NULL AUTO_INCREMENT,
  lottery_id_fk INT UNSIGNED NOT NULL,
  name VARCHAR(200) NOT NULL,
  quantity INT UNSIGNED NOT NULL DEFAULT 1,
  company_id_fk INT UNSIGNED NULL DEFAULT NULL,
  priority INT NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  KEY lottery_prize_lottery_idx (lottery_id_fk),
  KEY lottery_prize_company_idx (company_id_fk),
  CONSTRAINT lottery_prize_lottery_fk FOREIGN KEY (lottery_id_fk) REFERENCES lottery (id) ON DELETE CASCADE ON UPDATE CASCADE,
  CONSTRAINT lottery_prize_company_fk FOREIGN KEY (company_id_fk) REFERENCES company (id) ON DELETE SET NULL ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE lottery_ticket (
  id INT UNSIGNED NOT NULL AUTO_INCREMENT,
  lottery_id_fk INT UNSIGNED NOT NULL,
  login_login_name_fk VARCHAR(100) CHARACTER SET utf8mb3 COLLATE utf8mb3_general_ci NOT NULL,
  reason VARCHAR(30) CHARACTER SET ascii NOT NULL,
  created DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY lottery_ticket_unique (lottery_id_fk, login_login_name_fk, reason),
  KEY lottery_ticket_login_idx (login_login_name_fk),
  CONSTRAINT lottery_ticket_lottery_fk FOREIGN KEY (lottery_id_fk) REFERENCES lottery (id) ON DELETE CASCADE ON UPDATE CASCADE,
  CONSTRAINT lottery_ticket_login_fk FOREIGN KEY (login_login_name_fk) REFERENCES login (login_name) ON DELETE CASCADE ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE lottery_winner (
  id INT UNSIGNED NOT NULL AUTO_INCREMENT,
  lottery_id_fk INT UNSIGNED NOT NULL,
  prize_id_fk INT UNSIGNED NOT NULL,
  login_login_name_fk VARCHAR(100) CHARACTER SET utf8mb3 COLLATE utf8mb3_general_ci NOT NULL,
  drawn DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  status VARCHAR(20) CHARACTER SET ascii NOT NULL DEFAULT 'drawn',
  notified DATETIME NULL DEFAULT NULL,
  PRIMARY KEY (id),
  KEY lottery_winner_lottery_idx (lottery_id_fk, login_login_name_fk),
  KEY lottery_winner_prize_idx (prize_id_fk),
  KEY lottery_winner_login_idx (login_login_name_fk),
  CONSTRAINT lottery_winner_lottery_fk FOREIGN KEY (lottery_id_fk) REFERENCES lottery (id) ON DELETE CASCADE ON UPDATE CASCADE,
  CONSTRAINT lottery_winner_prize_fk FOREIGN KEY (prize_id_fk) REFERENCES lottery_prize (id) ON DELETE CASCADE ON UPDATE CASCADE,
  CONSTRAINT lottery_winner_login_fk FOREIGN KEY (login_login_name_fk) REFERENCES login (login_name) ON DELETE CASCADE ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```
