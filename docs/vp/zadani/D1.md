# D1 Losování pro registrované (+ D1b online kategorie)

- **Větev roadmapy:** V2 Losování (viz [ROADMAP.md](../ROADMAP.md))
- **Issue:** #46
- **Řešitel:** Claude
- **Stav zadání:** schváleno (Petr, 2. 11. 2026 – pokyn k implementaci); **revize 15. 11. 2026 (los na místě s platností,
  kola losování, nevyzvednuté výhry) čeká na schválení** – do schválení se nemění DB

## Cíl

Do losování se zapojí jen registrovaný návštěvník (role `visitor`) jedním kliknutím ve svém profilu; za doplněný profil
dostane los navíc. Na místě se losuje podle rozpisu (dnes jednou za hodinu) a hraje jen ten, kdo je pravděpodobně
v areálu: los se aktivuje při příchodu a po čase propadne, akce vázané na přítomnost ho prodlouží.
Výherce to uvidí v profilu; nevyzvednutou výhru si může vyzvednout v sídle organizátora (výzva e-mailem).
Změna akce: „Losování jen pro registrované, losy za profil, losování v aplikaci“ (R 3.1, R 4, S 5)
a volitelně „Online losování pro nepřítomné“ (R 7, D1b).

## Současný stav

- Losování dnes běží mimo web: na úvodní stránce a v profilu návštěvníka je odkaz na anketu
  (`local/site/najdisi/static/vp/uvod/content/program.php`, `vp-profil-navstevnika/template.php`) a „slosování o ceny“.
- Na místě se losuje jednou za hodinu podle rozpisu časů losování; výherce vyvolává moderátor na pódium.
- Web neví, kdy návštěvník areál opustil (žádné odbavení při odchodu).
- DB events nemá nic pro losování. Účet návštěvníka je v events v tabulce `login` (vzniká synchronizací Z1 při prvním
  přístupu přihlášeného uživatele), profil v `visitor_profile` (jméno, příjmení, telefon, CV, dopis).
- E-mail účtu je jen v DB auth (`registration.email`).

## Rozsah

Patří sem:
- **Losování** (může jich být víc, např. „Veletrh 2027 – na místě“ a „Veletrh 2027 – online“): název, popis, odkaz na pravidla,
  od kdy do kdy se lze zapojit, stav (příprava → otevřeno → uzavřeno → vylosováno), příznak online (D1b),
  údaje o vyzvednutí nevyzvednutých výher (od kdy, do kdy).
- **Kola losování (rozpis):** losování má jedno nebo více kol s plánovaným časem (na místě např. 11:00, 12:00, …;
  online jedno kolo). Organizátor rozpis zakládá a upravuje v administraci.
- **Ceny:** název, počet kusů, volitelně firma, která cenu věnuje (`company`), volitelně kolo, ve kterém se losuje
  (bez kola = losuje se v kterémkoli kole podle pořadí `priority`).
- **Zapojení:** v profilu návštěvníka tlačítko „Zapojit se do losování“ se souhlasem s pravidly → los za registraci.
  Los navíc za doplněný profil (pravidla níže) se vyhodnotí před každým kolem. Návštěvník vidí, v kterých losováních je
  a kolik má losů.
- **Los na místě – platnost (nové 15. 11.):** u losování na místě se losy účastníka účastní kola, jen když má platnou
  *přítomnost*:
  - **vydání při příchodu** – obsluha u vchodu (administrace na telefonu) vyhledá návštěvníka a vydá los (aktivuje přítomnost);
    návštěvník se musí předem zapojit (souhlas s pravidly) – pokud není, zapojí se na místě jedním kliknutím v profilu;
  - po vydání se los účastní kol, jejichž plánovaný čas je **nejdříve za `issueMinMinutes`** (výchozí 30 min) od vydání,
    a to **nejvýš `issueRounds` kol** (výchozí 2); pak propadne;
  - **prodloužení (refresh)** – akce vázaná na přítomnost (seznam v konfiguraci, každá s vlastním intervalem, výchozí 60 min)
    prodlouží platnost do `čas akce + interval` (prodlužuje jen dopředu, nikdy nezkracuje); los se účastní kol s časem do konce platnosti;
  - opakované vydání u vchodu po propadnutí = nové vydání (znovu 30 min a 2 kola); při platném losu = prodloužení;
  - jedno kolo, jedna osoba = jedna šance podle počtu losů; kdo v losování vyhrál, v dalších kolech už nehraje;
  - **návštěvník v profilu vidí**: los vydán v …, hraje v kolech …, platí do …, případně „los propadl – prodloužíte ho …“;
  - každé vydání a prodloužení se zaznamená (kdo, kdy, jaká akce) kvůli kontrole.
- **Losování v administraci** (role `events_administrator`): náhled kola (počet účastníků s platnou přítomností a jejich losů),
  tlačítko „Vylosovat“ (jedna cena nebo všechny ceny kola), losy váží šanci, jeden účastník vyhraje v jednom losování
  nejvýš jednu cenu (zda i napříč losováními, např. na místě a online, určuje konfigurace `lottery.oneWinAcrossLotteries`,
  výchozí ne); protokol (čas, počty, kdo losoval).
- **Dva způsoby losování na místě** (oba nad stejnou službou):
  - *projektor* – v administraci tlačítko „Losovat“, výsledek na samostatné celoobrazovkové stránce pro projektor
    (cena, křestní jméno výherce, žádný e-mail ani příjmení); stránka se obnovuje sama po každém tahu;
  - *telefon* – stránka administrace upravená pro mobil: velké tlačítko „Losovat“, výherce (jméno a příjmení pro vyvolání hlasem),
    tlačítko „Převzal na místě“.
- **Výhra a vyzvednutí (nové 15. 11.):**
  - výherce vyvolá moderátor na pódium; výherce vidí v profilu „Vyhráli jste …“ hned po tahu;
  - převzetí na místě obsluha označí „Převzal na místě“;
  - **nevyzvednutá výhra** se nepřelosovává; po skončení akce organizátor tlačítkem pošle výhercům, kteří nepřevzali,
    e-mail s výzvou k vyzvednutí v sídle organizátora od dalšího pracovního dne (adresa a doba v konfiguraci, datumy
    od–do u losování, předvyplněné na další pracovní den);
  - v sídle stačí doložit znalost e-mailu účtu: obsluha výherce vyhledá podle e-mailu a označí „Převzal v sídle“;
  - notifikace v mobilní aplikaci (budoucí PWA) – mimo D1; oznámení výherci je oddělený krok (rozhraní), aby šlo
    později přidat notifikaci a e-mail zůstal záložní cestou.
- Na webu veřejně jen ceny a počet výherců, nikdy jména (rozhodnuto 2. 11.).
- Všechny procesy losování (na místě i online) se později zrevidují s organizátorem – úkol #74; nastavení, které se může
  změnit, je v konfiguraci.

Nepatří sem:
- losy za navštívené stánky (D2, V13 – po QR B1/B3), za přednášky, „přiveď kamaráda“ (F), studentské mise;
- akce prodlužující platnost kromě ručního potvrzení obsluhou – přidají se s balíky, které je zavedou (sken QR u stánku,
  přednáška…), jako nový klíč v konfiguraci a jedno volání služby;
- vstupenka s QR (V4) – vydání losu u vchodu zrychlí, D1 vyhledává ručně;
- živé obrazovky a notifikace (PWA), mobilní aplikace;
- ukazatel úplnosti profilu (H2b) – D1 použije jednoduché pravidlo, po H2b se nahradí.

## Databáze

Migrace `migrations/events/2026111xxxxxxx_lottery.sql` – 6 nových tabulek v `utf8mb4` (stávající tabulky se nemění).
Návrh z 1. 11. ještě nikde neběžel, proto se mění přímo (bez přidávací a odebírací verze).

| Tabulka | Sloupce (zkráceně) |
|---|---|
| `lottery` | `id`, `name`, `description`, `online`, `status`, `join_from`, `join_until`, `rules_url`, `pickup_from`, `pickup_until`, `created` |
| `lottery_round` *(nová 15. 11.)* | `id`, `lottery_id_fk`, `draw_at` (plánovaný čas), `status` (`planned`, `drawn`), `drawn` (skutečný čas), `drawn_by` |
| `lottery_prize` | `id`, `lottery_id_fk`, `round_id_fk` → `lottery_round` (SET NULL), `name`, `quantity`, `company_id_fk` → `company` (SET NULL), `priority` |
| `lottery_ticket` | `id`, `lottery_id_fk`, `login_login_name_fk` → `login`, `reason` (`registrace`, `profil`, později `stanek`…), `created`, `removed`, `removed_by`; unikátní (losování, login, důvod) |
| `lottery_presence` *(nová 15. 11.)* | `id`, `lottery_id_fk`, `login_login_name_fk`, `issued`, `issued_by`, `eligible_from`, `valid_until`; unikátní (losování, login) |
| `lottery_presence_event` *(nová 15. 11.)* | `id`, `presence_id_fk`, `event` (klíč akce, `vydani`, `rucne`, později `stanek`…), `created`, `created_by`, `valid_until` (platnost po akci) |
| `lottery_winner` | `id`, `lottery_id_fk`, `round_id_fk`, `prize_id_fk`, `login_login_name_fk`, `drawn`, `status` (`drawn`, `claimed`, `called`, `claimed_office`), `claimed`, `claimed_by`, `notified` |

- Platnost přítomnosti: kolo `R` se účastní, když `eligible_from <= R.draw_at` a (`R.draw_at <= valid_until`).
  `valid_until` při vydání = plánovaný čas `issueRounds`-tého kola s časem ≥ `eligible_from` (méně kol → poslední kolo);
  při prodloužení `valid_until = MAX(valid_until, čas akce + interval)`. Rozhoduje plánovaný čas kola, ne skutečný
  (zpožděné kolo nikoho nevyřadí). Pozdější změna rozpisu už vydané platnosti nepřepočítá (zaznamenáno v protokolu).
- Odebraný los navíc (`removed`) se před dalším kolem znovu nepřidá.
- Sloupce s cizím klíčem na `login` mají znakovou sadu rodiče (utf8mb3), jinak cizí klíč nevznikne.
- Smazání loginu smaže jeho losy, přítomnost a výhry (`ON DELETE CASCADE`).
- Návrat zpět: `DROP TABLE lottery_winner, lottery_presence_event, lottery_presence, lottery_ticket, lottery_prize, lottery_round, lottery;`
- Celé SQL je v příloze na konci zadání.

## Konfigurace (`ConfigurationEvents`, klíč `lottery`)

```php
'lottery' => [
    'oneWinAcrossLotteries' => false,
    'presence' => [
        'issueMinMinutes' => 30,   // los hraje nejdřív v kole za 30 min od vydání
        'issueRounds' => 2,        // a nejvýš ve 2 kolech
        // akce prodlužující platnost: klíč => minuty (platnost do času akce + minuty);
        // klíč, který tu není, platnost neprodlouží (akce se jen zaznamená)
        'refresh' => [
            'rucne' => 60,         // ruční potvrzení přítomnosti obsluhou (D1)
            // 'stanek' => 60,     // sken QR u stánku (až D2/B1)
            // 'prednaska' => 60,  // účast na přednášce
        ],
    ],
    'pickup' => [
        'place' => 'sídlo organizátora, adresa…',   // do e-mailu výzvy
        'hours' => 'po–pá 9–15 h',
        'days' => 30,              // předvyplněná doba vyzvednutí od dalšího pracovního dne
    ],
    'bonusRules' => [/* viz níže */],
    'cv' => ['minBytes' => 10240, 'minChars' => 200, 'minWords' => 30],
],
```

Prodloužení volá kód akce jedním řádkem `LotteryPresence::refresh($loginName, 'stanek')`; vypnutá nebo nenastavená akce
nic nedělá. Seznam akcí tak roste s balíky a zůstává na jednom místě.

## Rozhraní

- Model (vzor modulu Events): `Lottery…`, `LotteryRound…`, `LotteryPrize…`, `LotteryTicket…`, `LotteryPresence…`,
  `LotteryPresenceEvent…`, `LotteryWinner…` (Dao, Repo, Entity, hydrátory).
- Služba `Events\Service\LotteryDraw`: výběr výherce s vahou podle počtu losů (`random_int`, kryptograficky bezpečný),
  jen z účastníků s platnou přítomností pro kolo (u online všichni zapojení), bez výherců z předchozích tahů téhož losování;
  čistá logika s rozhraním pro zdroj náhody (kvůli testům).
- Služba `Events\Service\LotteryPresence`: `issue()`, `refresh(loginName, event)`, `isEligible(presence, round)`,
  výpočet platnosti z rozpisu kol; čas přes rozhraní hodin (kvůli testům).
- **Losy navíc podle konfigurace** (`lottery.bonusRules`): seznam pravidel, každé = název důvodu
  (`reason` v `lottery_ticket`), počet losů a třída kontroly (rozhraní `Events\Service\Lottery\BonusRuleInterface`
  s metodou `isSatisfied(string $loginName): bool`). Nová pravidla se přidají jako další třída a řádek konfigurace, bez změny DB.
- **Pravidlo „doplněný profil“** (`CompleteProfileRule`, 1 los): vyplněné `name` a `surname` (každé aspoň 2 písmena)
  a CV, které projde kontrolou:
  - nahraný dokument `cv_document` povoleného typu (PDF, DOC, DOCX, ODT) a velikosti aspoň `lottery.cv.minBytes` (návrh 10 kB), **nebo**
  - texty `cv_education_text` a `cv_skills_text` dohromady aspoň `lottery.cv.minChars` znaků (návrh 200), aspoň
    `lottery.cv.minWords` různých slov (návrh 30) a bez dlouhých opakování stejného znaku/slova.
  Organizátor může los navíc ručně odebrat („CV nevyhovuje“); návštěvníkovi zůstane los za registraci.
- Oznámení výherci přes rozhraní `WinnerNotifierInterface` (D1: zobrazení v profilu + e-mail; později notifikace PWA).

  veřejný blok s cenami a počtem výherců, úprava textů na úvodní stránce (místo odkazu na anketu „Zapojte se v profilu“) –
  vše podle přepínače.
- E-maily: `lottery-winner.php` (výhra, jen u online losování nebo pokud výherce nebyl vyvolán na místě) a

## Přepínač

`vp.losovani` – vypnuto: routy vrací 404, v profilu ani administraci není blok losování, úvodní stránka zůstává s odkazem na anketu.

## Akceptační kritéria

1. Nepřihlášený návštěvník vidí výzvu „Zaregistrujte se a zapojte se do losování“, zapojit se nemůže.
2. Přihlášený návštěvník se zapojí jedním kliknutím se souhlasem s pravidly; mimo období `join_from`–`join_until` to nejde;
   podruhé se nezapojí (jeden los za registraci). Zástupce firmy se zapojit nemůže (tlačítko nevidí, API vrátí 403).
3. Návštěvník s doplněným profilem má 2 losy, ostatní 1; počet losů vidí v profilu. CV z nesmyslného krátkého textu
   los navíc nedá; ručně odebraný los navíc se do dalších kol nepočítá.
4. **Platnost na místě** (rozpis 11:00, 12:00, 13:00, 14:00; výchozí konfigurace):
   - los vydaný v 10:40 hraje v 11:00 a 12:00, ve 13:00 už ne; v profilu je „los propadl“;
   - hranice 30 min: los vydaný v 10:30 hraje v 11:00, vydaný v 10:31 v 11:00 nehraje (hraje ve 12:00 a 13:00);
   - prodloužení ve 12:30 (60 min) → hraje i ve 13:00, ve 14:00 ne;
   - prodloužení v 10:45 platnost nezkrátí (hraje stále v 11:00 a 12:00);
   - opakované vydání ve 13:10 po propadnutí → hraje ve 14:00 (a dalším kole, je-li);
   - zapojený bez vydaného losu v kole na místě nehraje; online losování přítomnost nevyžaduje.
5. Vylosování kola: každá cena kola má tolik výherců, kolik má kusů (pokud je dost účastníků); nikdo nevyhraje dvakrát
   v jednom losování (výherce v dalších kolech nehraje); šance odpovídá počtu losů (test na 10 000 tazích, tolerance).
6. Výherce vidí výhru v profilu hned po tahu. „Převzal na místě“ / „Převzal v sídle“ se zapíše s časem a obsluhou.
7. Výzva k vyzvednutí přijde jen výhercům, kteří nepřevzali, s místem a dobou vyzvednutí; podruhé se nepošle.
   Obsluha v sídle najde výherce podle e-mailu.
8. Online losování (D1b) funguje stejně, jen bez přítomnosti, s jedním kolem a textem o zaslání ceny.
9. Vypnutý přepínač = web jako dnes; ostatní sites beze změny.

## Testy

- Unit: `LotteryPresence` (hranice 30 min, počet kol, prodloužení jen dopředu, opakované vydání, málo kol v rozpisu,
  pevné hodiny), `CompleteProfileRule`, `LotteryDraw` (váhy, jen platná přítomnost, bez opakování výherce,
  málo účastníků, deterministický zdroj náhody), šablony e-mailů (`HtmlMessage`).
- Integrační: Dao všech tabulek, unikátnost losu a přítomnosti, kaskády při přejmenování a smazání loginu.
- Ruční: rozpis 3 kol s posunutými časy → 4 testovací návštěvníci (vydání v různých časech, jeden prodloužený,
  jeden s profilem) → vylosování kol → převzetí / nepřevzetí → výzvy ve fake SMTP.

CREATE TABLE lottery (
  id INT UNSIGNED NOT NULL AUTO_INCREMENT,
  name VARCHAR(200) NOT NULL,
  description TEXT NULL,
  online TINYINT(1) NOT NULL DEFAULT 0,
  status VARCHAR(20) CHARACTER SET ascii NOT NULL DEFAULT 'draft',
  join_from DATETIME NULL DEFAULT NULL,
  join_until DATETIME NULL DEFAULT NULL,
  rules_url VARCHAR(500) NULL DEFAULT NULL,
  pickup_from DATE NULL DEFAULT NULL,
  pickup_until DATE NULL DEFAULT NULL,
  created DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE lottery_round (
  id INT UNSIGNED NOT NULL AUTO_INCREMENT,
  lottery_id_fk INT UNSIGNED NOT NULL,
  draw_at DATETIME NOT NULL,
  status VARCHAR(20) CHARACTER SET ascii NOT NULL DEFAULT 'planned',
  drawn DATETIME NULL DEFAULT NULL,
  drawn_by VARCHAR(100) NULL DEFAULT NULL,
  PRIMARY KEY (id),
  KEY lottery_round_lottery_idx (lottery_id_fk, draw_at),
  CONSTRAINT lottery_round_lottery_fk FOREIGN KEY (lottery_id_fk) REFERENCES lottery (id) ON DELETE CASCADE ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE lottery_prize (
  id INT UNSIGNED NOT NULL AUTO_INCREMENT,
  lottery_id_fk INT UNSIGNED NOT NULL,
  round_id_fk INT UNSIGNED NULL DEFAULT NULL,
  name VARCHAR(200) NOT NULL,
  quantity INT UNSIGNED NOT NULL DEFAULT 1,
  company_id_fk INT UNSIGNED NULL DEFAULT NULL,
  priority INT NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  KEY lottery_prize_lottery_idx (lottery_id_fk),
  KEY lottery_prize_round_idx (round_id_fk),
  KEY lottery_prize_company_idx (company_id_fk),
  CONSTRAINT lottery_prize_lottery_fk FOREIGN KEY (lottery_id_fk) REFERENCES lottery (id) ON DELETE CASCADE ON UPDATE CASCADE,
  CONSTRAINT lottery_prize_round_fk FOREIGN KEY (round_id_fk) REFERENCES lottery_round (id) ON DELETE SET NULL ON UPDATE CASCADE,
  CONSTRAINT lottery_prize_company_fk FOREIGN KEY (company_id_fk) REFERENCES company (id) ON DELETE SET NULL ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE lottery_ticket (
  id INT UNSIGNED NOT NULL AUTO_INCREMENT,
  lottery_id_fk INT UNSIGNED NOT NULL,
  login_login_name_fk VARCHAR(100) CHARACTER SET utf8mb3 COLLATE utf8mb3_general_ci NOT NULL,
  reason VARCHAR(30) CHARACTER SET ascii NOT NULL,
  created DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  removed DATETIME NULL DEFAULT NULL,
  removed_by VARCHAR(100) NULL DEFAULT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY lottery_ticket_unique (lottery_id_fk, login_login_name_fk, reason),
  KEY lottery_ticket_login_idx (login_login_name_fk),
  CONSTRAINT lottery_ticket_lottery_fk FOREIGN KEY (lottery_id_fk) REFERENCES lottery (id) ON DELETE CASCADE ON UPDATE CASCADE,
  CONSTRAINT lottery_ticket_login_fk FOREIGN KEY (login_login_name_fk) REFERENCES login (login_name) ON DELETE CASCADE ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE lottery_presence (
  id INT UNSIGNED NOT NULL AUTO_INCREMENT,
  lottery_id_fk INT UNSIGNED NOT NULL,
  login_login_name_fk VARCHAR(100) CHARACTER SET utf8mb3 COLLATE utf8mb3_general_ci NOT NULL,
  issued DATETIME NOT NULL,
  issued_by VARCHAR(100) NULL DEFAULT NULL,
  eligible_from DATETIME NOT NULL,
  valid_until DATETIME NULL DEFAULT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY lottery_presence_unique (lottery_id_fk, login_login_name_fk),
  KEY lottery_presence_login_idx (login_login_name_fk),
  CONSTRAINT lottery_presence_lottery_fk FOREIGN KEY (lottery_id_fk) REFERENCES lottery (id) ON DELETE CASCADE ON UPDATE CASCADE,
  CONSTRAINT lottery_presence_login_fk FOREIGN KEY (login_login_name_fk) REFERENCES login (login_name) ON DELETE CASCADE ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE lottery_presence_event (
  id INT UNSIGNED NOT NULL AUTO_INCREMENT,
  presence_id_fk INT UNSIGNED NOT NULL,
  event VARCHAR(30) CHARACTER SET ascii NOT NULL,
  created DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  created_by VARCHAR(100) NULL DEFAULT NULL,
  valid_until DATETIME NULL DEFAULT NULL,
  PRIMARY KEY (id),
  KEY lottery_presence_event_presence_idx (presence_id_fk, created),
  CONSTRAINT lottery_presence_event_presence_fk FOREIGN KEY (presence_id_fk) REFERENCES lottery_presence (id) ON DELETE CASCADE ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE lottery_winner (
  id INT UNSIGNED NOT NULL AUTO_INCREMENT,
  lottery_id_fk INT UNSIGNED NOT NULL,
  round_id_fk INT UNSIGNED NULL DEFAULT NULL,
  prize_id_fk INT UNSIGNED NOT NULL,
  login_login_name_fk VARCHAR(100) CHARACTER SET utf8mb3 COLLATE utf8mb3_general_ci NOT NULL,
  drawn DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  status VARCHAR(20) CHARACTER SET ascii NOT NULL DEFAULT 'drawn',
  claimed DATETIME NULL DEFAULT NULL,
  claimed_by VARCHAR(100) NULL DEFAULT NULL,
  notified DATETIME NULL DEFAULT NULL,
  PRIMARY KEY (id),
  KEY lottery_winner_lottery_idx (lottery_id_fk, login_login_name_fk),
  KEY lottery_winner_round_idx (round_id_fk),
  KEY lottery_winner_prize_idx (prize_id_fk),
  KEY lottery_winner_login_idx (login_login_name_fk),
  CONSTRAINT lottery_winner_lottery_fk FOREIGN KEY (lottery_id_fk) REFERENCES lottery (id) ON DELETE CASCADE ON UPDATE CASCADE,
  CONSTRAINT lottery_winner_round_fk FOREIGN KEY (round_id_fk) REFERENCES lottery_round (id) ON DELETE SET NULL ON UPDATE CASCADE,
  CONSTRAINT lottery_winner_prize_fk FOREIGN KEY (prize_id_fk) REFERENCES lottery_prize (id) ON DELETE CASCADE ON UPDATE CASCADE,
  CONSTRAINT lottery_winner_login_fk FOREIGN KEY (login_login_name_fk) REFERENCES login (login_name) ON DELETE CASCADE ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
